# React 上手路线 · 4 周专项（面向本项目前端）

> **定位**：你已经在用 Next 16 + React 19 写页面（`notelab-b` / `notelab-c`），所以这份路线不教「什么是组件」，而是把**容易写错的地方**逐条钉死：状态从哪来、什么时候该重渲染、服务端与客户端边界在哪。
>
> **学完的标准**：能在 `notelab-c` 里独立加一个带表单、列表、分页、错误处理的页面，并且知道它为什么不会重复请求、不会无限渲染。

---

## 先建立三个判断

| 判断 | 错误做法 | 正确做法 |
|---|---|---|
| 状态放哪 | 什么都塞进组件 `useState` | **能被推导的不要存**；跨组件用提升或 Context |
| 什么时候重渲染 | 靠 `useEffect` 手动同步 | 渲染由状态驱动，副作用才用 `useEffect` |
| 服务端还是客户端 | 全站 `"use client"` | 默认服务端；只有需要交互/浏览器的组件才加 |

**一句话**：React 不是「用 JS 操作 DOM」，而是「用状态描述 UI」。你写的每一行 `useEffect`，都应该能回答「这是在同步什么外部系统」。

## 第 1 周：组件、props、状态

**任务**

1. JSX 本质：`<div>` 会被编译成函数调用；`{}` 里是表达式，不是语句。
2. props 单向流动；`children` 是特殊 prop。
3. `useState`：为什么 `setCount(count + 1)` 连写三次只加 1（批处理 + 闭包快照）；用函数式更新 `setCount(c => c + 1)`。
4. 列表与 `key`：为什么不能用数组下标当 key（删除中间项会复用错组件状态）。
5. 条件渲染、`&&` 的 0 陷阱（`0 && <X/>` 会渲染 0）。

**动手**：在 `notelab-c` 里做一个「任务清单」页（先用本地状态，不接接口）

```
输入框 + 添加按钮 → 列表 → 勾选完成 → 删除 → 全部完成/清除已完成
要求：编辑时不能整列表重渲染（用 React DevTools 的 Highlight updates 验证）
```

**验收**

- [ ] 能解释「为什么连写三次 `setCount(count+1)` 只加 1」
- [ ] 能说出用 index 当 key 会出什么具体问题
- [ ] 能在 DevTools 里看出哪些组件重渲染了

## 第 2 周：副作用与数据请求

**任务**

1. `useEffect`：依赖数组、清理函数、**竞态**（快速切换 tab 时旧请求覆盖新结果）。
2. 数据请求的三种写法：`useEffect + fetch`、`SWR` / `react-query`、**服务端组件里直接取**。本项目的 B 端用的是自封装的 `apiJson`，先读懂它。
3. 错误与加载态：三态（loading / error / data）必须都处理。
4. `useMemo` / `useCallback`：**只在有性能证据时用**，滥用反而增加复杂度。
5. `AbortController` 取消请求（组件卸载 / 参数变化）。

**动手**：把第 1 周的任务清单接上真实接口

```
GET  /api/tasks?page=1        → { items, total }
POST /api/tasks               → 新建
PATCH /api/tasks/{id}         → 完成/取消
要求：切换分页时取消上一个请求；失败时显示可重试的错误态
```

**验收**

- [ ] 快速切页不会出现「旧数据覆盖新数据」
- [ ] 请求失败有明确提示，不是白屏
- [ ] 能说出这个页面一共发了几次请求、为什么

## 第 3 周：Next.js App Router（本项目的真实形态）

**任务**

1. 目录即路由：`app/(admin)/xxx/page.tsx` 的路由组不进 URL；本仓 `basePath` 是 `/admin`。
2. 服务端组件 vs 客户端组件：`"use client"` 的边界在哪、为什么边界越低越好。
3. 数据获取：服务端组件里 `await`、`fetch` 缓存策略、`revalidate`。
4. 路由跳转：`<Link>` vs `router.push`，什么时候必须用后者。
5. 本项目特有的两个坑：
   - **页面守卫**：`(admin)/layout.tsx` 用 `/api/menu` 下发的 `pages` 做精确匹配，新增页面必须登记到 Java 的 `PageRoutes`
   - **不要加 `/api` rewrites**：`/api/*` 由 nginx 直达 Java，加了会绕路

**动手**：在 `notelab-b` 里加一个只读页面（例如「学习路线」这种纯展示页）

```
要求：服务端组件渲染、不加 "use client"、数据从已有接口来
验收：能在浏览器看源码（Ctrl+U）里直接看到内容（说明是服务端渲染）
```

**验收**

- [ ] 能说出一个组件该不该加 `"use client"`
- [ ] 能解释「为什么新增页面要同时改 Java 的两处常量」
- [ ] 能看懂 `layout.tsx` 的守卫逻辑并说出它的局限（不是安全边界）

## 常见坑（本项目踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面刷新 404 | 用了子路由但守卫是精确匹配 | 用 `?id=` 查询参数承载二级页，或把路径登记进 `PageRoutes` |
| 无限请求 | `useEffect` 依赖里放了每次新建的对象/函数 | 依赖放原始值，或用 `useCallback` 稳定引用 |
| 改了代码线上没变 | 只 push 没部署 / 构建失败但老进程还在 | 看 `sync-deploy` 日志；构建失败不会重启，这是设计 |
| 深色模式闪白 | 首帧没加防闪烁脚本 | 参考现有 `layout` 的内联脚本，别自己造 |
| 接口 401 但明明登录了 | B/C 两端 token 不互认 | 确认打的是哪一端、用的哪个 Cookie |
